# How to use this vault

## Purpose
This is not a general knowledge base.  
It is a **principles atlas** — a carefully curated collection of fundamental rules that generate understanding across domains.

## Adding a new principle

1. Copy `_templates/Principle.md`
2. Place it in the correct domain/subdomain folder
3. Fill every section (especially Relationships)
4. Update the relevant `README.md` indexes
5. Add links from related principles

## Recommended Obsidian plugins
- Graph view (core)
- Backlinks (core)
- Dataview (optional, for dynamic indexes)
- Templater (optional)

## Linking conventions

- Use `[[wikilinks]]` for Obsidian
- Also keep relative Markdown links so GitHub remains readable
- Prefer linking to the principle note, not to folders

## Growth rules

- Never force a principle into the wrong domain just to fill a folder
- Prefer creating a new subdomain when a cluster of related principles appears
- Keep the hierarchy shallow (max 3–4 levels)
- Every principle must have at least 2–3 relationships filled

## Review cadence
- When you truly understand a principle, mark `status: stable`
- Periodically review the Relationships sections — they are the highest leverage part of the vault.
